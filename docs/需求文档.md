## 回函管理

### 回函列表

#### 业务说明

系统提供回函管理列表，以便于业务人员统一查看、筛选和处理全部已回函记录。

列表以「一封函证一行」展示，并给出该封回函当前所处的处理进度，业务人员据此判断下一步动作。

业务人员可通过列表上的入口进入各处理环节，无需在多处菜单间切换。

#### 业务规则

- 列表排序规则为「回函时间倒序」，不因处理动作重排行序。
- 同一函证多次回函时以最新一次为最终有效回函；历史回函标「已被覆盖，可不处理」，保留留痕但不参与风险提示与统计。
- 回函结果完成 = 表单里所有必填字段都有值（无论值是从本页填的，还是从核查页采纳带出的）；AI 核查项表没表态不影响完成。三个进度只回答「下一步做什么」，不代表数据被锁定。
- 回函结果保存后，仍未表态的核查项自动按「采纳」记一条留痕（把结果带出、列表「核查事项复核」随即变「已复核」）；人已经表过态的项不动，自动带出不覆盖人的判断。
- 快递信息与回函结果是两个独立步骤、没有先后：先填结果、后确认快递信息也可以，两个勾各自独立。
- 全部检测项「尘埃落定」才写入本列表（失败也算落定：那封照样入表、不给结论、可「重新识别」）；未提交切分归属的一批一律不写库。
- 核验事项不含快递面单检测；银行函证没有发函件可对照，故不设「发函回函一致性检测」，其相符性由「回函是否相符检测」给出。
- 识别结论只作为建议：业务人员不修改识别结果本身，只决定是否采用；识别过程显示在「智能核查状态」（这一封整体核到哪一步）与「智能核查进度」（逐项核完没有）两列，各检测项的依据明细在「核查事项复核」列点开的核验页里看。
- 核验人与核验时间不单设列，下沉到展开行的留痕信息中展示。

#### 使用角色

- 业务人员
- 复核人员。

- 查看－包括：查看函证、回函快递信息、回函结果、核查事项复核详情。支持给到菜单权限的人员可查看回函记录信息，通过查询条件进行查询。

#### 页面字段说明

- 被询证单位：该封函证的被询证方 —— 往来函证为往来单位、银行函证为银行（本页表头随之标注「（银行）」）。数据来自函证系统、随回函记录带入；关键字查询也按它匹配。
- 函证编号：函证系统在发函登记时产生的编号，唯一标识一封函证，等宽字体展示。一封函证可多次回函，每次回函各自成行、共用同一编号，以「回函次序」区分；关键字查询也按它匹配。
- 智能核查状态：这一行的机器核查跑到哪了 —— 未开始 / 正在核查（标签带扫光动效）/ 已核查 / 核查失败 四态，与站内风险、相符性同一套配色语义。它是后面结论的前置条件：核查没跑完时「回函是否相符」还没有可显示的结论；没有核查任务的行（演示种子 / 历史回函）直接视为已核查。
- 智能核查进度：本类函证的全部智能核查项逐个给状态标识 —— 浅灰短横（未核查）· 在跑的像素网格（正在核查）· 对勾 / 叉（完成 / 失败），随真实核查进度动态联动；悬停看每项此刻的情况，失败项提示可在「操作」列点「重新识别」重跑。它与右边「核查事项复核」共用同一份事项清单，但那格只报人的复核状态（待复核 / 已复核），逐项细节只在本列。
- 回函是否相符：该封回函的相符性结论；往来取自「印章核查」的落章区域判定、银行取自「回函是否相符检测」，也可在「回函结果填写」页直接填写。
- 核查事项复核：该封回函的核验待办；随核验页里的逐项表态更新 —— 还有事项没表态显示「待复核」，全部表态后显示「已复核」，点它进核验页。
- 回函信息录入进度：快递信息 / 回函结果两步的可点步骤条；快递信息一步按该行是否确认过快递信息打勾，回函结果一步按该行是否填过回函结果打勾。
- 快递单号：该回函的快递单号；银行函证同一包裹的多封回函共用同一单号。
- 回函记录表（展开行，8 列）：回函次序 · 发函记录编号 · 发函方式 · 回函快递公司 · 快递单号 · 回函数据登记时间 · 回函情况 · 操作。发函记录编号与发函方式来自函证系统，回函快递公司由「导入快递数据」代入，回函数据登记时间是录入函证系统的时刻。

#### 输入、输出

**输入：**

| 数据项 | 来源 | 说明 |
|---|---|---|
| 回函记录 | 系统内生成 | 上传回函文件并完成识别、归属后自动生成 |
| 函证基础信息 | 函证系统对接 | 函证编号、被询证单位、发函记录编号等 |
| 快递数据 | 人工导入（Excel） | 按快递单号匹配，补全快递公司、地址、收件人等信息 |
| 查询条件 | 人工录入 | 关键字（被询证单位 / 函证编号 / 发函记录编号）、发函方式、回函信息录入进度 |

**输出：**

| 数据项 | 去向 | 说明 |
|---|---|---|
| 回函列表数据 | 页面展示 | 一封函证一行；排序为「回函时间倒序」，不因处理动作重排 |
| 处理进度 | 页面展示 | 待确认快递信息 / 待填写回函结果 / 已完成（只表达"下一步做什么"；两个步骤的完成态各自独立展示） |
| 展开行明细 | 页面展示 | 历次回函记录 + 归属来源 / 核验 / 最近修改留痕 |

### 回函上传－往来函证

#### 业务说明

业务人员收到被询证单位寄回的往来函证回函，按快递件扫描成 PDF 后上传系统。

系统识别回函件中的二维码与文本信息，自动判断这份回函归属哪一封函证。

#### 业务规则

- 往来函证与银行函证的识别流程一致，差异在于归属匹配方式与面单处理方式。
- 往来函证的面单页是每段自己的尾页（一封函证对一张面单），不单独切分成段。

#### 使用角色

- 业务人员。

#### 权限说明

- 菜单权限：业务人员拥有回函管理菜单权限。
- 功能权限：上传－包括上传往来函证回函文件、填写上传信息、提交识别。
- 列表数据权限：不涉及。

#### 功能说明

本功能接收往来函证的回函件：业务人员把按快递件扫描出的 PDF（拼接件）上传，系统据此创建识别任务，随后在「回函切分与归属」界面把文件切成段、逐段归属到函证。

| 名称 | 类型 | 规则/说明 |
|---|---|---|
| 上传往来函证回函 | 按钮 | 打开上传弹窗，选择回函文件（支持多份） |
| 上传文件 | 上传 | 支持 PDF 格式，单份文件对应一个快递件 |
| 最后页是否快递面单 | 单选 | 选择「是」时，识别与切分时按「每段尾页为快递面单」处理，并识别面单上的快递单号 |

### 回函上传－银行函证

#### 业务说明

银行按年度回函，同一家银行的多个年度函证装在一个快递里寄回，业务人员扫描后上传。

系统识别回函件内容，并对文件中的快递面单页识别条形码，得到快递单号。

#### 业务规则

- 银行函证常见「多封函证 + 一张面单」——同一快递件内的多封回函共用同一个快递单号，故归属环节需支持一张面单管辖多个函证段。
- 面单识别采用两级处理以控制成本：先做廉价的版面／条码存在性判定筛掉正文页，再对候选页做条码定位解码；识别结果异步回填，不阻塞业务人员进入切分环节。

#### 使用角色

- 业务人员。

#### 权限说明

- 菜单权限：业务人员拥有回函管理菜单权限。
- 功能权限：上传－包括上传银行函证回函文件、填写上传信息、提交识别。
- 列表数据权限：不涉及。

#### 功能说明

### 回函切分与归属

#### 业务说明

一份扫描件里常常装着多封回函，需要人工把文件切成几段、并把每段归到对应的函证上。

银行函证还会出现「多封函证 + 一张面单」：面单页需要单独切成一段，由它管辖前面的几个函证段。

#### 业务规则

- 未点「确定」（未提交）时，本批一律不写入回函列表：识别照跑，但落库、启动阶段二、回填核验都不发生；提交后仍要等该段全部检测项尘埃落定才写库（失败也算落定）。
- 初稿按类型分：往来 = 二维码已切好的分段（可微调）；银行 = 整份一段、由用户自己切。每段一个归属下拉。
- 同包裹的段用包裹标签区分（8 档固定色板循环），包裹号才是主标识，不在段与段之间画竖线。
- 银行侧「快递面单识别」与切分并行：面单页是识别结果，到达后系统才把它预切成独立段；用户已切分处理过的不再另切，一律以人工切分为准（界面不提供任何“系统改切分”的入口）。
- 快递单号只在面单段校验一次（银行侧不校验重复 —— 多段共用同一单号是正常形态）；人工填写的单号按“页”记录，用户改切分后值仍留在含该页的那一段上。
- 人工单号与系统识别不一致时，在该行人工值后挂一枚「系统识别 …」标签作提醒：不改人工值，也不提供“采用识别值”的动作。
- 银行侧切分有「手动 / 智能」两条路，默认手动；智能为可选增强（点一次把切分 / 归属 / 单号认好）。已动过切分时必须先确认「将用识别结果替换你当前的切分」。
- 识别切分是异步能力，效率须在实施前实测；本界面不得把切分绑死在识别结果上 —— 没有识别结果时，切分、归属、单号录入三件事照常可做。

### AI 智能核验－发函回函一致性检测

#### 业务说明

业务人员需要把回函件上的数据与发函底稿逐格核对，确认被询证单位填写的内容与发函是否一致。

系统把发函件中的每张数据表格识别出来展示，回函中与发函不一致的地方就地标红，业务人员只看差异即可。

#### 业务规则

- 不再左右并排：右栏宽度有限，两表并排会让金额列换行、同一行要左右来回看；发函 × 回函的正反对照在左侧预览里完成。
- 四个比对结论的口径：一致（两侧取值相同）／不一致（取值不同，单元格标红、悬停看差异额）／未列示（发函有、回函未列示）／新增（回函多出）。
- 左侧预览默认取景：本项＝双栏均分（两件对照）；印章核查 / 手写体识别＝回函件放大、发函用印件折叠。
- 本页签不设「人工确认」列：差异属客观事实、不需要逐行采纳，「回函结果不相符处的描述」的出处是「手写体识别」页（银行侧是「回函是否相符检测」页）；本页签的进入与页脚「采纳 / 不采纳」口径见「回函列表」。

#### 使用角色

- 业务人员
- 复核人员。

#### 权限说明

- 菜单权限：业务人员、复核人员均拥有回函管理菜单权限。
- 功能权限：查看－包括查看发函／回函原件、查看逐表对比结果、查看差异明细。
- 列表数据权限：不涉及。

#### 功能说明

本页面把发函件中的每张数据表格识别出来逐表展示，回函中与发函不一致的单元格就地标红，业务人员只看差异即可完成核对。

### AI 智能核验－印章核查

#### 业务说明

业务人员需要确认回函件上是否加盖了被询证单位印章、印章是否落于有效区域，以判断该回函是否可信。

系统在原件上叠加批注框标出印章位置与落章区域，业务人员直接对着原件核对。

#### 业务规则

- 印章定位框是语义性描边，不是装饰性边框。
- 印章与相符性的关系按类型分流：往来 —— 印章是相符性的判据（落「信息证明无误」区→相符，落「信息不符」区→不相符）；银行 —— 印章不参与相符性判定（相符性只看询证事项逐项核对）。

### 函证查看与文件预览

#### 业务说明

业务人员看完 AI 结论后要回到原文核依据 —— 印章究竟落在哪个区、金额识别对不对、手写说明写了什么，都要打开原件逐页翻看得清才行。

本功能提供「查看函证」全屏弹窗：顶部一条基础信息带，下面一排页签切换本次函证的不同文件，预览区多页连续滚动并支持缩放；历史回函也从这里看。

#### 业务规则

- 四个明细入口（查看 / AI 核验 / 回函快递信息 / 结果填写）统一为全屏弹窗，由列表页单一互斥状态驱动，同一时刻只开一个；全屏后遮罩不可见，故关闭入口保留三处：右上角 ×、Esc、底栏按钮。
- 承载形态为多页连续滚动：逐页垂直排列并懒渲染（进入视口前 400px 才绘制）；默认「适应宽度」—— 回函文字密集，适宽最易读。
- 缩放范围 25%~500%，可用底部浮动工具条（缩小 / 百分比预设 / 放大、适应宽度、适应页面、1:1、当前页 / 总页数），也支持 Ctrl + 滚轮与触控板捏合；普通滚轮只滚动、不缩放。缩放过程先用 CSS 拉伸撑住视觉，停手 260ms 后按新比例重渲染以保证清晰。
- AI 批注不绘制进原文件：采用「原件渲染层 + 批注叠加层」双层结构，原件二进制保持不可变（审计证据链要求），批注以结构化数据（页号 + 归一化坐标 + 类型 + 文案 + 置信度 + 归属来源）承载；只有导出 / 打印 / 归档这类需要固定留痕的场景，才在服务端合成为 PDF / 图片。
- 批注坐标按页面百分比记录，与显示尺寸解耦 —— 缩放、滚动、换屏时始终贴合文件内容；印章定位框的含义写在框自带的标签上，页面上没有常驻图例。
- 渲染引擎为 pdf.js，格式限制为只认 PDF —— Word / 图片需先转 PDF（第三方 iframe 无法叠加坐标标注，KKFileView 组件保留备用）。

### 快递数据导入

#### 业务说明

往来函证的物流信息（快递公司、寄件人、地址、电话）在面单上往往不完整，需要用快递系统导出的 Excel 补齐。

业务人员要的不是再来一遍识别流程，而是「导进去、告诉我哪些对上了、哪些没对上」，确认后直接写到对应回函上。

#### 业务规则

- 匹配纽带是快递单号：回函文件里的面单给出「这封回函对应哪个函证」，导入的 Excel 给出「这一单快递的完整信息」，两者以单号合并 —— 即使面单上只有单号，也能通过导入的数据补齐收发件信息。
- 按快递单号与回函面单识别出的单号匹配，抽屉里逐行给出「配上 / 配不上」；点「确认代入」才真正写入 —— 写的是当前有效那一次回函的快递公司与运单号。
- 收件人三项（寄件人 / 联系电话 / 发件地址）不写回回函 —— AI 与快递数据都确定不了，只能在「回函快递信息」里人工补。
- 未匹配时给出原因：该函证尚未上传回函（面单未识别），或运单号填写有误；可核对后重新导入，或对相应函证执行「回函快递信息」手工补填。
- 本功能不走多阶段识别流程（不涉及切分与二维码识别），导入后直接给出匹配结果。
- 主要服务往来函证；银行函证的回函信息以四要素归属为主。
- 面单不是单独上传的文件 —— 面单页在回函拼接件里、单号由 AI 在识别阶段读出；单独导入的是快递详细信息 Excel，且这一步可选。

#### 使用角色

- 业务人员。

#### 权限说明

- 菜单权限：业务人员拥有回函管理菜单权限。
- 功能权限：维护 —— 包括导入快递数据、确认代入。
- 列表数据权限：不涉及。

#### 功能说明

列表主操作行「导入快递数据」打开的抽屉：摘要行给出文件信息与三条计数（解析 N 行 / 成功代入 M 条 / 未匹配 K 条），下面是逐行明细表；确认代入后写入对应回函。

| 名称 | 类型 | 规则/说明 |
|---|---|---|
| 导入快递数据 | 按钮 | 主操作行入口：带入内置匹配结果并直接打开抽屉（原型实现，没有真实选文件与解析过程） |
| 摘要行 | 展示区 | 文件名 + 大小 + 导入时间，以及解析 N 行 / 成功代入 M 条 / 未匹配 K 条 |
| 逐行明细表 | 表格 | 运单号 / 快递公司 / 发件人 / 联系电话 / 发件地址 / 归属函证（函证编号 + 被询证单位）/ 匹配结果 |
| 未匹配行 | 提示 | 悬停给原因（尚未上传回函 / 运单号填写有误），并说明可核对后重新导入 |
| 确认代入 | 按钮 | 确认后把快递公司与运单号写入当前有效那一次回函 |

#### 页面字段说明

- 逐行明细的运单号、快递公司、发件人、联系电话、发件地址均来自导入的 Excel。
- 归属函证是匹配得出的：函证编号 + 被询证单位。
- 写回回函的字段只有两个 —— 快递公司与运单号，其余三项只在抽屉里核对用。

#### 输入、输出

**输入：**

| 数据项 | 来源 | 说明 |
|---|---|---|
| 快递数据 Excel | 人工导入 | 含快递单号、快递公司、地址、姓名、电话等详细信息 |

**输出：**

| 数据项 | 去向 | 说明 |
|---|---|---|
| 快递公司、运单号 | 回函记录 | 确认代入后写入当前有效那一次回函 |
| 匹配结果清单 | 本抽屉 | 逐行展示配上 / 配不上与未匹配原因 |
