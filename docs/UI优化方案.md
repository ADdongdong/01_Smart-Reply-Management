# 回函管理智能化工作台 · UI 优化方案

> 走查对象：`src/theme.ts`、`src/styles/global.css`、`src/layouts/WorkbenchLayout.tsx`、
> `src/pages/ReplyList.tsx` 及 `src/components/*`（18 个组件）。
> 走查方式：逐文件读码 + 令牌/对比度实算 + 窄屏溢出量估算。

---

## 一、现状评估

项目已经完成了一轮高质量的设计系统建设：令牌化（色/字/距/影/圆角）、去线条化（线条压到
发丝级，层次交给留白与多层阴影）、语义色收敛（红/绿只用于「风险 / 相符」）、动效只用
`transform`/`opacity`、补齐 `aria-label` 与 `:focus-visible`。

**所以问题不在「风格好不好看」，而在三件事：**

| # | 问题域 | 一句话结论 |
|---|---|---|
| A | **结构一致性** | 同层级的六个业务入口用了三种容器形态；页面骨架缺少「页面头」这一层锚点 |
| B | **可读性 / 密度** | 9 列表格无分组线索；同一句话在「进度列」与「操作列」说两遍；风险两档视觉不可区分 |
| C | **健壮性 / 可访问性** | 全站零响应式；顶部导航在 ≤1280px 被静默裁切；中性标签文字对比度 4.17:1 未达 AA |

## 二、检查发现的问题

### P0 · 结构性问题

#### P0-1 六个业务入口，三种容器形态

| 入口 | 当前形态 | 代码 |
|---|---|---|
| 查看函证 | 全屏 Modal（100vw × 100vh） | `FullscreenModal` |
| AI 智能核验 | 全屏 Modal | `FullscreenModal` |
| 回函快递信息 | 全屏 Modal | `FullscreenModal` |
| 回函结果填写 | 全屏 Modal | `FullscreenModal` |
| 智能识别工作台 | 右侧抽屉 **920px** | `RecognitionDrawer` |
| 快递数据导入 | 右侧抽屉 **900px** | `ExpressImportDrawer` |

用户在同一张表上点不同入口，容器形态会跳变：全屏覆盖 ↔ 右侧抽屉。同一层级的动作应当
只有一种「打开方式」。更严重的是 `ReplyResultModal` 内部又叠了一个 `width={1280}` 的
内嵌 Modal（查看完整核验），形成 **三级层叠**，Esc 与焦点返回路径难以预期。

#### P0-2 全站零响应式，且顶部导航在 1280px 就会被裁掉

- 全项目仅一处媒体查询：`@media (prefers-reduced-motion: reduce)`（`global.css:87`）。
  **没有任何宽度断点。**
- `ReplyList` 的表格写死 `scroll={{ x: 1344 }}` —— 视口 < 1344px 必然横向滚动。
- 顶部导航容器是 `flex: 1; overflow: hidden`（`WorkbenchLayout.tsx:65`），
  10 个一级导航项**超宽时直接裁掉尾部，没有「更多」收纳**。

实算：视口 1280px 时，可用宽度 = 1280 − 48（头部 padding）= 1232px；
导航实际需要 ≈ 980px，品牌区 ≈ 134px，右侧操作区 ≈ 151px，合计 **≈ 1265px > 1232px**。

> **结论：在 1280×800 的笔记本上，「函证文件」这一项会被裁掉一半；
> 窗口再缩到 1200px，被裁掉的就是当前激活项「回函管理」本身。**

#### P0-3 导航缺少「我在哪」的第二重线索

10 个平级导航里只有 1 项可用，其余 9 项以灰字 `<span cursor:not-allowed>` 呈现，
**和可用项的视觉差异只有颜色深浅一档**，用户会反复点击无反应。同时页面内没有面包屑、
没有页面标题，进入「回函管理」后对「这是审计作业 → 函证 → 回函管理」的层级无从感知。

### P1 · 视觉层级与语义

#### P1-1 高风险与中风险视觉完全相同

`src/components/Marks.tsx:57`

```ts
high:   { text: '高风险', color: 'var(--c-risk-high-text)', bg: 'var(--c-risk-high-bg)' },
medium: { text: '中风险', color: 'var(--c-risk-high-text)', bg: 'var(--c-risk-high-bg)' },
```

两档只有**文字**不同，色相、底色、字重完全一致。后果是：扫视表格时「高风险」被
大量「中风险」稀释，而审计场景里两者处置动作完全不同（高风险必须复核依据，
中风险通常只需留痕）。

#### P1-2 AI 语义与主色语义几乎不可区分

```css
--c-primary-bg: rgba(59, 91, 219, 0.08);
--c-ai-bg:      rgba(59, 91, 219, 0.05);   /* 只差 3% 不透明度 */
```

`README` 声明 AI 的识别口径是「浅底 + 虚线 + ✦ 前缀」，但 **代码里没有任何一处虚线**，
实际只剩「✦ 前缀」这一条。两档底色在屏幕上肉眼几乎同色。

#### P1-3 标签尺寸与圆角刻度失控

- **标签高度出现 3 种**：`.ai-chip` 16px；`BankTextRecognition` 的 Tag `line-height:18px`；
  `RiskTag` / `MatchTag` / `VerifyBadge` 20px。
- **圆角出现 7 种**：2px（`.seal-box span`）、3px（`PageThumbs`）、4px（`--radius-tag`）、
  6px（`--radius-control`）、7px（`VerificationPanel` 分段控件）、8px（`--radius-card`）、
  10px（分段控件轨道）。
  而文档声称「圆角统一三级」。

#### P1-4 低置信度胶囊与风险标签同底不同字色

```ts
// Marks.tsx:34 —— 低置信度
{ color: 'var(--c-text-1)', background: 'var(--c-risk-high-bg)' }
// Marks.tsx:58 —— 高风险
{ color: 'var(--c-risk-high-text)', background: 'var(--c-risk-high-bg)' }
```

同一个红底，一个用墨色字、一个用深红字。读者会以为这是两种不同性质的语义。

### P2 · 信息密度与冗余

#### P2-1 「下一步」文案在一行里说了两遍

`ReplyList.tsx:47` 定义 `NEXT_STEP`，在「回函进度」列渲染
`下一步：确认回函快递信息`；同一行的操作列主按钮又写 `确认回函快递信息`。
代码注释说明这是刻意「严格同词」——但**同词的价值是「用户能对上」，不是「出现两次」**。
两次出现占据了本可用于其他信息的横向空间。

#### P2-2 「是否重新发函」列性价比极低

该列宽 104px，判定口径是「该函证回函次数 > 1」。8 行数据中只有 2 行为真值，
其余 6 行渲染一个 `—`。**用 104px 的固定宽度承载 25% 概率的一个布尔值。**

#### P2-3 9 列表头没有任何分组线索

表格语义上分三组：函证信息（2 列）/ 核验结论（3 列）/ 流程与操作（2 列）。
v2.3 为「去线」把**全部组间竖分隔线**一并删除后，9 列变成一条等距的直线，
横向定位只能靠数格子。

#### P2-4 两个同权重主按钮并排

`ReplyList.tsx:976` 与 `997`，两个上传按钮均为 `type="primary"`。
**一个屏幕上两个蓝色实心主按钮 = 没有主按钮**，且它们的差异（检测项不同）
只藏在 tooltip 里。

#### P2-5 三处「标签 + 值」用了三种标签宽度

| 位置 | 标签列宽 |
|---|---|
| `SealRecognition` 的 `InfoRow` | 132px |
| `ReplyResultModal` 表单 | 200px |
| `ReplyDocEntryModal` 字段网格 | 112px |

同一产品内同一种信息形态三种尺度，纵向跨页阅读时左边界跳动。

### P3 · 可访问性

#### P3-1 中性状态标签文字对比度不达 AA —— 实算 4.17:1

`RiskTag` 的 `none`、`MatchTag` 的「无法判定」、`VerifyBadge` 的「待核验」
都使用 `color: var(--c-text-3)` 叠在 `background: var(--c-tag-bg)` 上：

| 项 | 值 |
|---|---|
| 文字 | `rgba(29,33,41,.60)` |
| 底色 | `rgba(16,24,40,.05)` over `#fff` ≈ `#F3F4F5` |
| 合成后文字色 | ≈ `#737B7B` |
| **实测对比度** | **4.17 : 1** ✗（WCAG AA 小字要求 4.5:1） |

改为 `--c-text-2`（0.72）后实算 **6.07 : 1** ✓。这是一处**确定的合规缺陷**。

#### P3-2 导航占位项键盘不可达

`WorkbenchLayout.tsx:71` 使用 `<span>` + `cursor: not-allowed` 模拟禁用，
缺 `aria-disabled`，也无法被 Tab 聚焦——屏幕阅读器用户完全不知道这几项存在。

#### P3-3 表格操作只能鼠标到达

每行 2~3 个可聚焦元素 × 10 行 = 30+ 次 Tab 才能走完一页。缺少行级快捷键或
「操作」聚合按钮（`aria-haspopup`）。

---

### P4 · 工程侧（影响 UI 一致性）

- **重复结构未组件化**：「浅底无边框小标签」在 `Marks.tsx` ×3、`ReplyList.tsx` ×2、
  `BankTextRecognition.tsx` ×2、`ReplyList` 的 `SoftTag` ×1 —— 共 8 处手写同样的
  `height / padding / borderRadius / fontSize / whiteSpace` 组合。
- 大量行内 `style={{...}}`，令牌无法统一演进，改一个色要全局搜索。
- 现状 `ReplyList.tsx` 单文件 1141 行，含 5 个内联子组件与 9 列定义。

---

### P5 · 文档与数据不一致（顺带发现）

`README.md:85` 写「共 8 条 · 待人工确认 **4** · 已完成人工确认 **4**」，
但按 `src/mock/confirmations.ts` 实际计算：
`verifyStatus === 'pending'` 的行有 **5** 行（whzf0010005 / QS2024-031 /
whzf0010003 / whzf0010007 / whzf0010001），已完成 **3** 行。文档需更新为 **5 / 3**。

## 三、优化方案

### A. 令牌升级

```css
:root {
  /* —— 风险改为三档可区分 —— */
  --c-risk-high: #e5484d;  --c-risk-high-text: #b3261e;  --c-risk-high-bg: rgba(229, 72, 77, .12);
  --c-risk-mid:  #e8892b;  --c-risk-mid-text:  #a35a00;  --c-risk-mid-bg:  rgba(232, 137, 43, .16);
  --c-risk-low:  #3fa34d;  --c-risk-low-text:  #237804;  --c-risk-low-bg:  rgba(63, 163, 77, .13);

  /* —— 中性文字抬一档，修掉 4.17:1 的合规缺陷 —— */
  --c-text-neutral-tag: rgba(29, 33, 41, .72);   /* 标签内文字专用，实算 6.07:1 */

  /* —— AI 语义与主色分离：主色实心浅底 / AI 虚线描边 —— */
  --c-ai-bg: rgba(59, 91, 219, .05);
  --c-ai-line: rgba(59, 91, 219, .32);           /* 1px dashed 用 */

  /* —— 圆角收敛为三级（清掉 2 / 3 / 7 / 10 四个散值） —— */
  --radius-card: 10px;  --radius-control: 6px;  --radius-tag: 4px;

  /* —— 控件与标签的统一高度刻度 —— */
  --h-control: 32px;  --h-tag: 20px;
}
```

实测对比度（全部 ≥ 4.5:1）：高风险 5.58 / 中风险 4.52 / 低风险 4.88 / 中性标签 6.07。

### B. 页面骨架：补一层「页面头」

```
┌ 顶部导航（含「更多」折叠 + 面包屑回落） ────────────────────┐
├ 页面头   面包屑 · 标题         │         统计指标组（3 项）  ┤  ← 新增
├ 工具栏   筛选区 / 已选条件 / 主操作区（1 主 2 次）           ┤
└ 表格区   单行表头 · 7 列 · 展开行（回函记录表）               ┘
```

把「共 8 条 · 待人工确认 5 · 已完成 3」从工具栏右端（13px 灰字）提升为
**页面头右侧的指标组**——它就是用户打开页面的第一个问题（「今天还有几件事」）的答案。

### C. 表格

1. **加一条 22px 高的分组标签带**（仅 3 个组名 + 组边界处各一条发丝线），
   不在数据行里加任何竖线——保留 v2.3「去线」的成果。
2. **列数 9 → 8**，总宽 1344 → 1050（1280 屏免横向滚动）：
   - 删「是否重新发函」列，改为函证编号后的 `↻ 2 次` 徽标（hover 说明第几次 / 共几次）；
   - 「发函记录编号」等核对型字段全部收进展开行（原本已在展开行，列上不再重复确认）。
   - **展开行本身也已精简（v2.38）** —— 只留**一张「回函记录」表**（当前有效 + 历史合并，六列）；原「函件与物流」「AI 核验结论」两片字段网格移出：前者并入「查看函证」顶部基础信息，后者回到行操作区的「更多 → AI 核验」（核验要配着原件批注看才有意义）；核验 / 修改留痕收成表下一行 12px 小字。
3. **进度列改为「三段步进点 + 状态词」**，删掉「下一步：xxx」小字——
   动作只在操作列出现一次。
4. **操作列每行结构恒定**：`主按钮（这一步该做什么）｜查看｜更多 ▾`，
   已完成行的主按钮位改为灰字「已完成」，保持列内对齐。

### D. 容器形态统一

| 入口 | 优化后 |
|---|---|
| 查看 / 核验 / 快递信息 / 结果填写 / 智能识别 / 快递导入 | **统一为全屏工作区**：12px 24px 标题栏（标题 + 副标题 + 右侧状态）+ 内容 + 底栏 |

- 识别工作台由「右侧 920 抽屉」改为**全屏两栏**：左＝识别队列，右＝预览/归属确认。
- 移除 `ReplyResultModal` 内嵌的 1280 Modal，改为**右侧可折叠的核验明细栏**
  （同屏看依据，且不产生第三层弹窗）。
- 窄屏（< 1280px）时全屏工作区自动退化为 96vw 的接近全屏尺寸，保留 8px 边距。

### E. 响应式断点

| 断点 | 策略 |
|---|---|
| ≥ 1600 | 表格完整 7 列；工作区左 55% / 右 45% |
| 1280 – 1599 | 列宽压缩（v2.37 起不再有需要收起的列，「人工核验」列已从列表移除） |
| 1024 – 1279 | 工具栏两段换行；表格保留 5 列 + 横向滚动（此时才允许滚） |
| < 1024 | 导航折叠为「更多」；表格退化为**卡片列表**（一封函证一张卡） |

### F. 可访问性

- 中性标签文字改用 `--c-text-neutral-tag`（6.07:1）。
- 导航占位项改为真实 `<button disabled aria-disabled="true">`，进入 Tab 序列。
- 每行末尾聚合一个 `aria-haspopup="menu"` 的「更多」，行操作可全键盘完成。
- 焦点样式区分底：主色/红底元素上用 `outline: 2px solid #fff; outline-offset: 2px`。

### G. 组件抽取（消除 8 处重复）

```
components/Tags.tsx      <StatusTag tone="high|mid|low|neutral|ai|primary">
                         <MetaTag>           ← 替代 SoftTag / 各处手写小标签
components/PageHeader.tsx
components/MetricGroup.tsx
components/TableGroupBand.tsx
styles/patterns.css      把「标签 + 值」的三种宽度收敛为一处变量 --label-w
```

## 五、原型

配套可交互原型：**`docs/prototypes/回函管理优化原型.html`**（单文件、零依赖、双击即可在浏览器打开）

> **2026-09-22 同步**：本原型已改为**「系统当前实现的样子」** —— 以 `src/` 为基准，删掉了系统里没有的东西（顶部导航、双行分组表头、密度切换、列设置、拆分式上传按钮），并把外壳与列表页的规格（页面头、表头底色、卡片内边距、分组标题分级、展开区字段同行、标签两档）对齐到系统。**后续优化在这个基线上谈。**

**一个文件覆盖七种形态** —— 列表与全部明细入口都在里面，可互相跳转。

**页面头右侧另有「原型导航」下拉**（五个全屏工作区的**标题栏内各有一个同源入口** —— 工作区打开时要点后者，前者会被盖住；菜单是以浮层跟随触发点、层级高于工作区），把 **18 个场景**排成三组，点任一项即先复位到基线、再直达该界面 / 状态：

| 组 | 场景 |
|---|---|
| 列表页 | ① 表格形态 · ② 卡片形态（窄屏）· ③ 筛选无结果（空状态）· ④ 展开行（含历史回函）· ⑤ 已选筛选条件（chips） |
| 明细工作区 | ⑥ ①查看·往来 · ⑦ ①查看·银行 · ⑧ ②AI 核验·往来 · ⑨ ②AI 核验·银行 · ⑩ ③快递信息·有面单 · ⑪ ③快递信息·空态 · ⑫ ④结果填写 · ⑬ ④必填未处理（保存被拦下） |
| 识别工作台 | ⑭ ③切分·文件识别录入 · ⑮ ③切分·数据核对 · ⑯ ⑤识别·往来批次 · ⑰ ⑤识别·银行批次（两阶段 + 归属确认）· **⑱ ⑤识别·银行批次（询证事项逐项核对失败兜底）** |

七种形态如下：

| # | 界面 | 如何到达 |
|---|---|---|
| 1 | 回函管理列表（表格） | 首页 |

**实测记录**

- *2026-09-21（原型扩充期）*：结构 / 形态 62 项、交互闭环 19 项、修复复测 11 项、场景导航 62 项、导航回归 12 项 —— 全部通过，控制台零 error。实测中发现并修复 3 处缺陷：① 关键字筛选未读取输入值导致筛选与空状态完全失效；② ④「AI 核验结论」五行只有结论值、缺少项名；③ 列表「相符」标签未按 `byAi` 分流。
- *2026-09-22（同步为系统）*：批 A 28/29、批 B 20/21。两处 FAIL 均经复核为**断言写法问题**（把白色也算"有底色"；把「查询」漏算成主按钮），功能正确。
- *2026-09-22（往来切分与并行，v2.32）*：**26 项断言全过**。覆盖批次卡 → 切分 3 段 → 15 个 ⟳ 同时跑 → 一致性仍「待检测」→ 清单 3 行四列 → 点行联动高亮与跳页 → 点确定转只读 → 三段一致性同时跑完 → 往来界面无「阶段」字样 → 银行未受影响 → 17 场景 → 窄屏无横滚 → 零 error。**实测抓到并修复 1 处真实缺陷**：⑰ 场景的「打开即自动点确定」先在固定延时上踩空（切分渲染晚于延时，`querySelector` 取到 null 后静默不点），改轮询后又被打断（`startReco()` → `stopReco()` 会 `clearTimeout(autoTimer)`）—— 最终改为「标记 + `renderReco()` 渲染后检查」，不受定时器清理影响。
