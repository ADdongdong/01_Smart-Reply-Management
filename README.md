# 函证系统 · 回函管理智能化工作台（交互原型）

对函证产品「回函管理」模块做**智能化升级 + 前端界面与交互重构**的可交互原型。

## 启动

```bash
npm install
npm run dev      # http://127.0.0.1:5178
```

其他命令：

```bash
npm run build    # 生产构建
npm run preview  # 预览构建产物
```

> 环境：Node ≥ 18（已在 Node 24 / npm 11 验证）、Windows PowerShell（命令请用 `;` 分隔，勿使用 `&&`）。

## 技术栈

React 18 · TypeScript · Vite 5 · Ant Design 5 · react-router-dom 6 · dayjs

识别能力为**纯前端 Mock**：真实 PDF 的识别结果以预置数据承载，异步处理过程用定时器模拟，零后端依赖，开箱可跑。

## 改造前后对比

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 录入入口 | 回函登记 / 文件识别录入 / 按文件编号上传 / 快递数据导入 **4 个并列入口**，需人工判断走哪个 | **1 个统一上传入口**，系统自动判定往来 / 银行并分派处理方式 |
| 识别过程 | 同步阻塞，无进度反馈 | **异步执行 + 实时队列**，逐阶段可见「正在处理哪一封」 |
| 归档方式 | 往来按二维码、银行需人工重命名文件 | 往来按二维码解析出的**函证编号**归属；银行按**「银行名称 + 被审计单位名称 + 函证起始日期 + 函证截止日期」四要素**自动归属 |
| 质量把关 | 无，印章 / 科目金额 / 手写说明全靠人工核对 | **四类 AI 智能核验**：回函一致性检测、印章识别、银行函证文本识别、手写体识别 |
| 风险呈现 | 无 | 高风险行左侧红色标记条 + 风险标签（hover 查看原因） |
| 核验留痕 | 无 | 「已人工核验」徽标，含核验人与时间；支持 hover 追溯 |
| 重复发函 | 无处理规则，多次回函数据混杂 | **一封函证一行**，以最新一次回函为准，历次回函收进展开行 |
| 筛选区 | 3~4 行堆叠，占高约 200px | 默认单行（约 48px），高频 4 项外露，已选条件以可删除 chips 展示 |
| 表格 | 14 列、行高约 56px | 7 列**单行表头**（组间竖分隔线）、行高 38px；字段带 ✦ 标识可追溯 AI 来源与置信度 |
| 页面层级 | 标题 + 步骤条 + 筛选 + 操作行 + 表格，共 5 层 | **收敛为 3 层**：筛选区 → 主操作行 → 表格 |
| 统计 | 无 | 主操作行展示「共 N 条 · 待人工确认 X · 已完成人工确认 Y」 |
| 首次使用 | 无引导，需自行摸索 | 四步操作指引（**不自动弹出**，从主操作行「操作指引」或顶部导航问号图标打开）+ 空状态引导 + 字段级 tooltip |

## 核心设计原则

> **AI 只产出「建议 + 风险标签 + 置信度」，绝不自动落库。所有 AI 结果必须经人工确认才写入，并留下「已人工核验」留痕。**

这既满足审计证据链合规要求，也是「标注是否人工核验」功能的由来。

## 关键业务规则

### 1. 相符性由印章位置决定

「回函结果是否相符」**不是**用户主观填写的字段，而是由印章所盖区域决定：

```
印章识别（AI）→ 判定落章区域
   ├─ 落在「信息证明无误」区 → 建议：相符
   └─ 落在「信息不符」区     → 建议：不相符
        ↓ 携带判定依据与置信度
用户确认（可人工覆盖）→ 写入回函结果 → 打「已人工核验」标识
```

该规则在「AI 智能核验 → 印章识别」与「回函结果填写 → AI 建议条」两处以显式文案 + 可视化定位框呈现。

### 2. 重复发函：以最新一次回函为准

往来函证二维码编码的是**函证编号**，不是发函记录编号 —— 因此系统判断的是「这份回函属于哪封函证」，无需关心是第几次发函。

同一函证多次回函时（如第 1 次回函不相符 → 重新发函 → 第 2 次回函）：

| | 处理 |
|---|---|
| **主行** | 只呈现**最近一次回函**（最终有效）的数据：回函进度、AI 风险、人工核验 |
| **展开入口** | **行首 chevron 箭头**（v2.20 起「回函次数」列已去掉，箭头成为唯一入口）；同一函证回函 ≥ 2 次的行，展开后可见「历次回函」表 |
| **展开区** | 列出历次回函（回函次序 / 发函记录编号 / 回函日期 / 快递单号 / 回函情况 / 状态），最新一次标 **最终有效**，其余标「已被覆盖，可不处理」 |
| **历史回函** | 回函资料与回函结果**非必填**、风险不提示、**不计入统计**，但保留查看与 AI 核验详情（审计留痕不丢） |
| **统计口径** | 「共 N 条」按函证数计；「待人工确认」= 最终有效回函的 AI 核验结果尚未人工确认 |

「最终有效」不靠人工标记，而是按**回函时间**自动推导 —— 新回函进来后自动成为最终有效，原回函自动降级为历史。

## 交互路径（建议体验顺序）

1. **可选** → 点主操作行的「**操作指引**」（或顶部导航问号图标）看四步说明，了解新的作业方式。**不会自动弹出**。
2. **回函管理主页面** → 表格为**一封函证一行**；主操作行右侧显示「共 8 条 · 待人工确认 4 · 已完成人工确认 4」。
   - 找到 `whzf0010005`（海通证券）与 `whzf0010001`（广发证券）—— 这两封函证各有 **2 次回函**。
   - **点行首 chevron 箭头**展开，可见上下两组：上面是「**当前有效回函 · 第 2 次 · 回函时间**」分组（函件与物流、修改留痕、AI 核验结论 —— 讲的都是最终有效那一次）；下面是「**历史回函（已被覆盖，仅供参考）**」表，**只列本次之前的**（第 1 次），每行末尾的「**查看**」可打开该次回函的只读详情。
3. **点击「上传回函文件」**（或直接拖入任意 PDF）→ 打开「智能识别工作台」。
   - 无本地文件时，可用抽屉内的**演示数据**按钮：往来函证拼接回函（9 页 / 5 封）、银行函证回函（4 页 / 1 封）。
4. **观察异步识别队列** → 每封函证先做「**归属匹配**」（只给结果，如「二维码解析成功 → 归属函证 whzf0010006（第 1 次回函）」），再**逐行**执行「**AI 智能核验**」；每个检测点用**圆形状态图标**标注进度（待检测 ○ / 检测中 ⟳ / 已完成 ✓ / 失败 ✕）并给出结论。
   - 演示数据中**第 7 页预设了二维码识别失败**，可体验「手动指定函证（按函证编号选择）/ 重新识别 / 跳过」的恢复动作。
   - 点击「**最小化**」，右下角出现**悬浮进度卡**，可边识别边浏览列表（不阻塞）；点卡片上的「展开」可回到工作台。
5. **识别完成后** → 对应函证所在行闪烁高亮，AI 核验列出现 `4/4` 进度徽标与风险色标。
6. **点击「AI 核验」** → 打开核验抽屉，依次查看：
   - **回函一致性检测**：发函 vs 回函科目金额逐行 diff，差异标红并给出差异额与处理动作。
   - **印章识别**：回函原件上的印章定位框（绿框常规 / 红框异常）+ 落章区域高亮 + 相符性判定。
   - **银行函证文本识别**：四要素识别值与发函底稿值对照（齐商银行样例）。
   - **手写体识别**：手写说明转录，可一键带入结果填写页。
7. **点击「资料录入」** → 回函资料录入页，AI 预填字段逐项「采纳 / 修改」，低置信度（<90%）字段黄色高亮提示，确认后记录核验人与时间。
8. **点击「结果填写」** → 回函结果填写页，「函证结果是否相符」默认由印章位置判定，AI 建议条可一键采纳；科目余额分录自动带入差异行。
9. **点击「删除」** → 弹出确认框；若该函证有多次回函，确认文案会说明「共 N 次回函记录将一并删除」。

## KKFileView 真实文件预览（已接入）

预览层提供**双引擎**，可在预览区右下角随时切换：

| 引擎 | 说明 |
|---|---|
| **真实文件** | iframe 指向 KKFileView 的 `onlinePreview`，渲染 `public/samples/` 下的真实样例 PDF —— 即生产环境的实际观感 |
| **AI 标注** | 项目内置的仿函证页面，用于承载印章定位框、「信息证明无误 / 信息不符」落章区域高亮、手写体转录等 AI 叠加层（iframe 里无法叠加） |

印章识别面板强制使用 AI 标注视图（定位框是其核心输出，`PdfPreview` 传 `forceMock`）。

### 链路与端口

```
浏览器 ──→ KKFileView(127.0.0.1:18012)
              │  容器去下载文件
              ↓
       host.docker.internal:5178/samples/xxx.pdf   ← 容器视角的「宿主机」
              ↑
       Vite dev server（已改为 host: true + allowedHosts 放行）
```

启动 KKFileView：

```powershell
docker run -d --name kkfileview -p 18012:8012 --restart=always keking/kkfileview:latest
```

**三个坑（都已在本项目中处理）**：

1. **不要用 Docker Desktop 的 Run 弹窗创建** —— 该镜像未声明 `EXPOSE`，弹窗里 Ports 一栏填不了，容器会以「无端口映射」启动，宿主访问不到。
2. **宿主机 8012 落在 Windows 保留端口区间内**（`netsh interface ipv4 show excludedportrange protocol=tcp` 可见 `7961-8060` 带 `*` 标记），Docker 无法绑定，故映射到 **18012**。
3. **Vite 默认校验请求的 Host 头**，容器用 `host.docker.internal` 回访会被拒（403）。已在 `vite.config.ts` 设置 `server.host: true` 与 `server.allowedHosts: ['host.docker.internal', ...]`。
