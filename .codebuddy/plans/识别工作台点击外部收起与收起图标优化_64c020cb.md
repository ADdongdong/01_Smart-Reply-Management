## 产品概述

修复「智能识别工作台」抽屉的两个交互缺陷：一是工作台展开后，点击工作台之外的左侧列表区域没有任何反应（无法收起）；二是底栏「收起」按钮前的图标（一条横线）观感差。修复后，用户可以直接点击左侧列表把工作台收起来，且左侧列表的视觉与现在完全一致；「收起」按钮的图标改为语义明确的向右双箭头。

## 核心功能

- **点击工作台外部区域即收起**：工作台展开时，左侧列表区域照常清晰可见、无变暗、无灰度；点击该区域任意位置，工作台向右滑出收起。属于工作台内（候选函证列表、上传区、底栏按钮）的点击不触发收起。
- **左侧列表视觉零变化**：不新增可见遮罩、不改变底色与文字可读性、不改变抽屉滑入动效，仅补上「点了会反应」这一能力。
- **「收起」按钮换图标**：由一条横线换为向右的双箭头 —— 工作台自右侧滑入，收起即向右滑出，方向语义一眼可读。按钮文案、位置、点击行为均不变。
- **其余关闭入口保持一致**：标题栏关闭按钮与 Esc 键收起行为不变，三处入口最终都走同一套收起逻辑。
- **不被波及**：「快递数据导入结果」抽屉与四个全屏明细弹窗（查看 / AI 核验 / 回函快递信息 / 回函结果）的点外关闭行为保持原样，其中全屏弹窗继续禁止点外关闭（防误触丢草稿）。

## 技术栈

沿用现有工程，不引入任何新技术：React 18 + TypeScript + Vite 5 + Ant Design 5.22.5 + @ant-design/icons 5.5.2。

## 实现方案

### 根因（已核实）

`src/components/RecognitionDrawer.tsx` 第 342-349 行的 `Drawer` 显式配置了 `mask={false}`。antd 的 Drawer 在不渲染遮罩层时，也就不会绑定「点击外部 → 触发 onClose」的行为，这正是「点左侧页面没反应」的直接原因。

`onClose` 本身已正确接到 `dispatch({ type: 'CLOSE_RECOGNITION' })`（`src/store/AppStore.tsx` 第 182 行），因此**状态层与数据流零改动**。

图标问题同在该文件：第 9 行 import 了 `MinusOutlined`，第 376 行的「收起」按钮使用它。已全量检索确认 `MinusOutlined` 在本文件仅此一处使用，替换安全。

### 关键决策

1. **让遮罩「存在但不可见」**：不是去掉 `mask`，而是保留遮罩层并把它做成视觉透明 —— 用 `styles` 的语义 DOM 键 `mask` 覆盖背景色为 `transparent`。这样 antd 会正常绑定点外关闭，而左侧列表看起来与改动前逐位一致。相比「用 `rootClassName` + 全局 CSS 覆写」的做法，`styles.mask` 是 antd 原生能力（Drawer 语义 DOM 自 5.13.0 起支持 `mask` 键），无需新增样式文件、不会产生全局副作用。

- 同一次改动里要把原有的 `styles={{ body: { paddingTop: 12 } }}` **合并保留**，不能覆盖丢掉。

2. **复用既有收起逻辑**：点外关闭、底栏「收起」、标题栏关闭、Esc 全部汇聚到同一个 `CLOSE_RECOGNITION`，不新增 action，不做特殊分支。收起后 `FloatingProgress` 悬浮进度卡是否出现，由已有的 reducer 逻辑决定，行为与现在点「收起」完全一致。
3. **图标替换**：`MinusOutlined` → `DoubleRightOutlined`（与用户选定的「向右双箭头」一致）。同步修正 `@ant-design/icons` 的 import：删除 `MinusOutlined`，新增 `DoubleRightOutlined`，保持该 import 列表的字母序。

### 性能与可靠性

本次改动为纯声明式配置 + 静态图标替换，无新增渲染、无新增监听、无状态扩展，渲染与交互开销与改动前一致（无 O(n) 级影响）。透明遮罩仅增加一个覆盖全视口的 div，样式为常量背景色，不触发重排。

### 不引入技术债

不新建组件、不新建样式文件、不改状态机、不改数据结构，全部改动落在既有文件内，符合项目「收敛入口、单一职责」的既有约定。

## 实施要点与风险控制

- **点击语义**：不可见遮罩会消费掉这一次点击（第一下只用于收起工作台），不会同时穿透触发左侧列表的行点击 / 展开图标 / 行内按钮 —— 这是标准抽屉交互，符合预期，但需实测确认。
- **拖拽上传不受影响**：遮罩只覆盖抽屉外部，抽屉内部的拖拽上传区与按钮点击应完全不受影响，需实测确认。
- **只渲染一层遮罩的时机**：遮罩仅在 `recognitionOpen` 为真时存在，收起后不残留、不拦截页面点击。
- **不扩散改动**：`ExpressImportDrawer`（未设 mask、保持默认可见遮罩）与 `FullscreenModal`（`maskClosable={false}`，四个全屏明细弹窗靠它防误触丢草稿）**必须保持原样**，不得顺手统一。
- **视觉约束**：不引入新色相（单一靛蓝 + 红绿仅作状态标签）；不新增动效，沿用 antd 既有滑入/滑出；时长与缓动不改。
- **同一文件串行编辑**：两处改动都在 `RecognitionDrawer.tsx`，必须先后执行，不可并行编辑（本项目曾出现并行编辑导致改动丢失）。
- **浏览器实测脚本的既有坑**：本机直接写 `%TEMP%\pw-verify\*.js` 会落成 0 字节，须先写 `.txt` 再复制为 `.js` 后运行；antd 会给两字按钮插入空格（如「确 认」），选择器需用宽松匹配。
