## 用户诉求

用户对识别工作台提出一个形态疑问：

> 既然这个智能识别的，缩小后是右下角的一个小弹窗，那是不是在智能识别的时候，直接做成弹窗会更好一些呢？而非抽屉呢？

**已核实并确认不改成弹窗**，形态保持右侧抽屉，理由三条：① 右下角小卡不是「抽屉的最小化」，而是「跨页面的任务指示器」—— 它有独立开关、抽屉展开时自动隐藏，作用是告知「活儿在跑，可以先去干别的」；② 需求文档以硬性要求写死了这个定位 —— N-01「识别过程不得阻塞用户操作」、N-02「可边识别边浏览列表」，而弹窗的语义是「打断式、一次做完就关」，直接冲突；③ 与四个全屏明细弹窗（查看 / AI 核验 / 回函快递信息 / 回函结果）的分工是有意的：那些是「任务型」，识别工作台是「长过程型」；位置上小卡在右下、抽屉从右侧滑出，本就同一侧。

## 用户决策

**保持抽屉，但把底栏「收起」正名为「最小化」** —— 形态与图标都不动，只改按钮文案。

理由（用户认可）：该按钮的实际行为是「关闭抽屉 + 显示右下角悬浮卡」，也就是**最小化**，叫「收起」没传达出「它会变成右下那张卡」。

## 核心改动

- 底栏按钮文案由「收起」改为「**最小化**」，图标继续用向右双箭头（表示向右滑出）
- 改完后，抽屉的「**最小化 ⇢**」与右下悬浮卡的「**展开 ↑**」正好构成一对反义词 —— 这是本次改名的主要收益：用户一眼能把两者对应起来
- 项目内其他语境下的「收起」全部保持原样（表格展开箭头、关闭悬浮卡本身、归属匹配的收起候选、iframe 加载遮罩等），不得误改
- 纯文案改动，无任何视觉、交互或行为变化

## 技术栈

沿用现有工程，不引入任何新技术与新依赖：React 18 + TypeScript + Vite 5 + Ant Design 5.22.5 + @ant-design/icons 5.5.2。

## 实现方式

### 核心判断

这是一次**用户可见文案的正名**，不是交互或架构改动：

- **只改文案与注释，不改任何代码标识符** —— action 仍是 `CLOSE_RECOGNITION`、状态字段仍是 `recognitionOpen`。沿用 v2.19「只改用户可见文案、不动内部标识符」的既定策略，把爆炸半径压到最小；改名若牵连 store / action 名，收益为零而回归风险显著上升。
- 在 `CLOSE_RECOGNITION` 的 action 定义处**补一句注释**锚定语义：该动作的用户语义是「最小化」—— 关闭抽屉并显示右下角悬浮卡，**不是销毁任务**。这是防止后人把它误读为「取消识别」的关键一笔。

### 实施注意（本机踩坑，务必遵守）

- **不要并行编辑同一文件** —— 本项目曾出现并行编辑导致改动丢失。`RecognitionDrawer.tsx` 的两处改动（按钮文案、注释）必须先后执行。
- **`replace_in_file` / `write_to_file` 出现过「报告成功但内容未落盘」** —— 改完必须逐条核对。**核对应优先用 `read_file` 读该行**：上一轮已实测到 `search_content` 的 `count` 模式会对确实已写入的内容报 0 命中，改用 `read_file` 才拿到真实状态。
- **写 `%TEMP%\pw-verify\*.js` 会落成 0 字节** —— 实测脚本须先写 `.txt` 再复制为 `.js`；playwright 只装在该目录，脚本必须在其中运行。
- **antd 会给「两个汉字」的按钮插空格** —— 原「收起」渲染为「收 起」，改为**四字**的「最小化」后不再受影响，实测选择器反而更稳。

### 性能与影响面

改动为静态字符串替换 + 一个 Tooltip，无新增渲染分支、无新增监听、无状态扩展，运行时开销与改动前一致。不新建文件、不新建样式、不改状态机与数据结构。

## 验证要求

1. `npx tsc --noEmit` 与 `npm run build` 均通过。
2. **浏览器实测（dev server 5178，playwright，脚本目录 `%TEMP%\pw-verify\`）**：

- 打开识别工作台 → 底栏按钮文案确为「**最小化**」
- 点「最小化」→ 抽屉关闭 **且右下角悬浮卡出现**
- 点悬浮卡的「**展开**」→ 抽屉重新打开、悬浮卡消失（确认「最小化 ⇄ 展开」闭环成立）
- 点外部区域、`Esc`、标题栏 `×` 行为不变（仍是同一条 `CLOSE_RECOGNITION`）
- **回归确认 v2.21 成果未被破坏**：遮罩仍为 `rgba(0, 0, 0, 0)`、点外部仍能最小化、点内部仍不触发
- 控制台零错误

3. **截图对照**：抽屉底栏（「最小化 ⇢」）与右下悬浮卡（「展开 ↑」）先后截图，确认这对文案读起来是一套。
4. **逐条核对落盘**：用 `read_file` 读取被改动的 4 个位置，确认文案已生效（不依赖写入工具返回值）。
