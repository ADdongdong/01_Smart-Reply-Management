## 二、评估 plannotator/effective-html（agent skills 集合）

用户问「这个 skill 有什么用、CodeBuddy 能用吗、怎么用」。结论：**能用，且与当前工作（做交互原型）高度相关**。

### 关键落点

1. **「咖啡色」根因**：`--c-risk-medium-text: #AD4E00` 是橙色的深色文字版（12px 小字达 4.5:1 对比度必然压棕）。根治 = 标签文字全部墨色、语义色只走底色与图形元素。约 20 处去色（`Marks` / `ConsistencyDiff` / `BankTextRecognition` / `RecognitionDrawer` / `ExpressImportDrawer` / `ReplyList` / `ReplyResultModal`）；回函进度去掉行首彩色圆点。

### 教训

- **replace_all 按「最具体优先」的精确模式分组**比逐处编辑高效得多：同一文件里「同构不同序」的内联样式（label 属性顺序不同）要先替换长模式再替换短模式，避免前缀误伤。

## 七、预览双视图答疑与切换器改造

用户问：左侧 KKFileView 默认 PDF 展示，为什么 AI 标注不在 PDF 上？设计目的是什么？并要求把切换按钮放大、放右上角。

**答疑结论（已写进 `PdfPreview.tsx` 组件注释与需求文档 7.2）**：

- 「真实文件」= KKFileView iframe 渲染真实样例 PDF，供人工阅读原文；「AI 标注」= 仿真函证页，承载印章定位框 / 落章区域 / 手写转录，供核对 AI 判断依据
- **不画在真实 PDF 上的原因**：KKFileView 是第三方 iframe（自渲染、跨域）无法叠加坐标层；且原型标注坐标是演示用模拟值，画上去位置对不上内容反而误导
- 生产落地：pdf.js 自渲染 + 坐标叠加层，标注即可直接落在真实文件上

**改动**：`PdfPreview.tsx` 切换器从右下角 Segmented（small）改为**右上角 `Space.Compact` 主色按钮组**（带图标文字：真实文件 / AI 标注；当前引擎主色实心；shadow-pop 浮层），`Segmented` import 移除。tsc / build 通过，浏览器实测两视图切换正常、控制台零错误。
