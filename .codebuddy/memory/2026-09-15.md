## 回函管理列表：重复发函展示重构（v2.1）

用户提出「重复发函的数据如何处理」，经三轮澄清后完成重构。

### 澄清结论（用户拍板）

1. **往来函证二维码编码的是函证编号**，不是发函记录编号 → 系统判断不出是第几次发函，归属落点就是**函证**
2. 以**最新一次回函**为准；不加「作废 / 被取代」概念，只标**【最终有效】**；历史回函资料非必填、风险可忽略
3. 去掉【待我处理 / 全部】切换，改为在主操作行展示「共 N 条 · 待人工确认 X · 已完成人工确认 Y」；「待人工确认」口径 = **仅指 AI 核验结果尚未人工确认**
4. 列表需**全量展示**所有回函记录 → 选定**方案 A：一封函证一行 + 展开历次**

### 关键设计判断

- 用户明确：**不必关心「第几次发函」**，「历史回函了几次，当前次就是第几次回函，可以计算出来」→ 因此「最终有效」**按回函时间自动推导**，不引入状态字段、不做人工标记
- 新回函进来自动成为最终有效，原回函自动降级为历史

### 改动清单

- `src/types/index.ts`：删除死字段 `seq`（全项目无读取，且 mock 值有重复）
- `src/mock/confirmations.ts`：重写。记录 id 规范为 `{函证编号}-{第几次回函}`；8 封函证 / 10 条回函记录（海通 `whzf0010005`、广发 `whzf0010001` 各有 2 次回函）；`CANDIDATE_RECORDS` 去掉 `sendRecordNo`（改为按函证编号指定）

## KKFileView 真实文件预览接入（v2.2）

用户已在本地跑起 kkfileview 容器，要求前端接上真实预览看整体效果。

### 环境结论（重要，后续复用）

- **镜像**：`keking/kkfileview:latest` 实际是 **4.1.0**；容器内监听 8012，配置目录为 `/opt/kkFileView-4.1.0/config/`（不是 `/opt/kkFileView/config/`）
- **不要用 Docker Desktop 的 Run 弹窗创建**：该镜像未声明 `EXPOSE`，弹窗里 Ports 一栏填不了 → 容器以「无端口映射」启动，宿主访问不到。必须命令行加 `-p`
- **宿主机 8012 落在 Windows 保留端口区间 `7961-8060`**（`netsh interface ipv4 show excludedportrange protocol=tcp` 可见带 `*` 的管理员排除），Docker 无法绑定 → 改用 **18012**
- **Vite 会校验请求的 Host 头**：容器经 `host.docker.internal` 回访 dev server 会被拒 **403** → 需 `server.host: true` + `server.allowedHosts: ['host.docker.internal', ...]`
- kkfileview 只认 HTTP URL、自己下载文件；容器内 127.0.0.1 是容器自身，访问宿主机必须用 `host.docker.internal`
- 调用方式：`/onlinePreview?url=<Base64(文件URL)>`，含中文文件名时先 `encodeURIComponent` 再 Base64

启动命令：

```powershell
docker run -d --name kkfileview -p 18012:8012 --restart=always keking/kkfileview:latest
```

### 前端改动

- `vite.config.ts`：`host: true` + `allowedHosts`
- `src/config/preview.ts`（新）：`KKFILEVIEW_PORT=18012`、`FILE_HOST=host.docker.internal:5178`、函证→样例文件映射、`buildKkPreviewUrl()`
- `src/components/KkFilePreview.tsx`（新）：iframe 预览 + 加载态 + 重载/新窗口工具条
- `src/components/PdfPreview.tsx`：双引擎（`real` / `mock`），右下角 Segmented 切换；`forceMock` 锁定 AI 标注
- `src/components/SealRecognition.tsx`：传 `forceMock`
- `public/samples/`：三个真实样例 PDF（重命名为英文：`huihan-0813.pdf` / `wanglai-1-SJ01YF001.pdf` / `bank-qishang-20240331.pdf`）
- 文档：README 与需求文档 → v2.2

### 验证

- kkfileview 容器 Up，`0.0.0.0:18012->8012/tcp`，HTTP 200
- 三个样例文件经 `onlinePreview` 均渲染成功（无错误页）

## UI 精修：多层阴影 + 透明度层级 + 卡片合并（v2.4）

用户附加 6 个 skill（distill / soft-skill / frontend-design / beautiful-shadows / swiss-design / web-design-guidelines）继续优化。

### skill 间的冲突与取舍（重要，后续沿用这个判断）

- **soft-skill** 要求逐段滚动入场动画、玻璃拟态、2rem 大圆角 → 那是**营销落地页**语言；而 **frontend-design** 明确反对「每段都 fade-and-slide-up、每张卡都加 hover 过渡，读起来像 AI 生成」。**站 frontend-design**：企业系统不做编排式动画。
- **swiss-design** 要直角 + Stone 色板 + IBM Plex → 破坏已有圆角体系、中文场景不适用；**只取其网格纪律 / 透明度层级 / 排版克制**。
- **beautiful-shadows** 的 Tailwind 类名用不上，但**多层叠加公式**可直接移植。

### 落地项

1. **多层柔和阴影**（提升最明显）：单层大模糊显脏，改为分层递进 —— `--shadow-card` 3 层 / `--shadow-hover` 4 层 / `--shadow-pop` 6 层（每层偏移与模糊成比例递减）
2. **文字层级改用中性透明度**：`--c-text-2: rgba(29,33,41,0.72)`（6.4:1）、`--c-text-3: rgba(29,33,41,0.6)`（4.6:1，达 AA）；去掉原来的蓝调灰，整页只有一种「墨色」
3. **合并筛选区与主操作行为一张卡**（distill）：页面 3 层 → 2 层
4. **8px 网格**：`.page` padding 改 24px，操作行 `marginTop: 24`
5. **焦点可见**：全局 `:focus-visible { outline: 2px solid var(--c-primary); outline-offset: 2px }` —— 此前键盘 Tab 看不出焦点，属无障碍缺陷
6. **自定义缓动** `--ease-out: cubic-bezier(0.16, 1, 0.3, 1)`，并同步到 antd 的 `motionEaseOut`
7. **圆角三级**：卡片 8 / 控件 6 / 标签 4
8. **表头排版精度**：`letter-spacing: 0.02em`、字重 500、颜色退到三级

### 明确不做

玻璃拟态 / 渐变 / 2rem 超大圆角 / 逐段入场动画 / 换字体 / 直角风格。

### 验证

`tsc --noEmit` 通过；`npm run build` 通过。

## 全局一致性修正 + 可访问性（v2.5）

用 `web-design-guidelines` skill 拉取 Vercel Web Interface Guidelines 规则做了一轮审计，修复如下问题。

### 1. 旧色值残留（真实 bug，9 处）

v2.3 改语义色时**只改了 CSS 变量，内联硬编码的 rgba 值没跟上**：

| 残留 | 位置 | 修正 |
|---|---|---|
| `rgba(47,91,234,...)` 旧主色 | 顶部导航当前项高亮、引导弹窗提示底色 | → `rgba(59,91,219,...)` |
| `rgba(245,34,45,...)` 旧高风险 | 落章区高亮、AI 建议条、差异明细 | → `rgba(229,72,77,...)` |
| `rgba(82,196,26,...)` 旧低风险 | AI 建议条、字段采纳底色 | → `rgba(63,163,77,...)` |
| `rgba(250,140,22,...)` 旧中风险 | 低置信度字段高亮框 | → `rgba(232,137,43,...)` |

> **教训（已写入长期约定）**：改语义色时必须**同时全局搜一遍硬编码的 rgba 值**，不能只改变量。这类残留会让页面出现「两种蓝/两种红」而不易察觉。

### 2. 顶部导航视觉修正

- Logo 的**多色渐变** `linear-gradient(135deg, #2F5BEA, #7C4DFF)` → 纯色 `var(--c-primary)`
  （渐变属装饰，且同时混用了主色与 AI 紫两个语义色）
- 导航当前项 `fontWeight: 600` → 500

### 3. 可访问性（对应 guidelines 反模式第 6 条）

- `RecognitionDrawer` 的上传拖拽区是 `<div onClick>` → 补 `role="button"`、`tabIndex={0}`、`onKeyDown`（Enter / Space 触发）与 `aria-label`

### 验证

`tsc --noEmit` 通过；`npm run build` 通过；旧色值全局搜索 **0 残留**。
