### 关键坑 1：CRG 把 CodeBuddy 当「项目级」平台

`code-review-graph install --platform codebuddy` 会往**当前仓库根**写 4 类文件：`.mcp.json` + `CODEBUDDY.md` + `.codebuddy\settings.json` + `.codebuddy\skills\`。而 **CodeBuddy 实际生效的是用户级 `~/.codebuddy/mcp.json`**（本会话可见的 GitHub / GitLab / Draw.io 等 server 都来自这里）。所以为达成「所有项目通用」，**没有在项目里执行 install**，而是手工把条目并入用户级配置。CRG 生成的原始条目（在临时沙箱里跑出来看的）为：

```json
{ "mcpServers": { "code-review-graph": {
  "command": "C:\\Users\\10355\\AppData\\Local\\pipx\\pipx\\venvs\\code-review-graph\\Scripts\\python.exe",
  "args": ["-m","code_review_graph","serve"],
  "cwd": "<项目根>", "type": "stdio" } } }
```

用户级采用版本（**去掉 `cwd`**，让它继承工作区目录 → 每个项目各自定位自己的图谱；补 `PYTHONUTF8=1`，官方称可避免 Windows 下 `Invalid JSON: EOF while parsing`；格式对齐现有条目，加 `autoApprove` / `timeout` / `disabled`）。

**未采用** `install` 写入的 hooks：其命令是 bash 语法（`cat >/dev/null`、`command -v`）且依赖 `git rev-parse`，Windows + 非 git 仓库下必然失败；也与用户「先用手动刷新」的选择一致。

### 关键坑 2：能力边界与文档不符，必须实测（已全部验证）

| 命令 | 非 git 仓库 | 说明 |
|---|---|---|
| `build` | ✅ 可用 | 走文件系统扫描；本项目 28 个源文件全部解析 |
| `watch` | ✅ **可用** | 临时沙箱实测：改文件后自动增量重解析，节点 4→5、FTS 重建、图谱自动刷新 |
| `update` | ❌ 报错 | `ERROR: Not in a git repository. 'update' requires git for diffing.` |
| `detect-changes` | ❌ 报错 | 同上，`--brief`（Token Savings 面板）也拿不到 |

**结论：非 git 项目靠 `build` 全量重建或 `watch` 自动刷新，不能靠 `update`。** 这一点与官方文档「非 git 也受支持」的说法不矛盾但有落差——受支持的是 build/scan，不是增量 diff。

其他实测可用：`status`（存在，README 没错、USAGE.md 漏列）、`architecture`（7 个社区）、`communities`、`search`（无嵌入时 `search_mode: keyword`）、`impact --files <路径>`（blast radius）、`dead-code`（本项目报 6 个）、`visualize`（生成 `.code-review-graph\graph.html`，419KB，内置 d3.v7.min.js）。
